# 30 ポートフォリオレビュー

## 目的

個別銘柄を別々に評価するだけでなく、家計・総資産・税・通貨・相関・機会費用を含むポートフォリオ全体として判断する。

## 正本

最新の `holdings*.csv` を保有数量・取得単価・口座種別の入力正本とする。現在値、前日終値、時価、前日比、損益、構成比は保存せず、レビュー時に取得・計算する。CSVに口座番号や個人識別情報を保存しない。

## 1. ユーザー条件

不足している場合は質問するか、仮定別に回答する。

- 投資目的、基準通貨、期間
- 生活防衛資金、大口支出、収入の安定性
- 許容損失額・最大ドローダウン
- 年金、投信、現金、不動産、負債を含む総資産
- 税務上の居住地、口座種別、含み益、売却制約
- 配当、成長、流動性、倫理・業種制約

## 2. CSV入力列

| 列 | 型・単位 | 説明 |
|---|---|---|
| code | text | 必須。4桁数字、または第1・第3文字が数字で、第2・第4文字に数字もしくは `B/E/I/O/Q/V/Z` を除く英大文字を使う4文字の国内証券コード。英字は大文字へ正規化する |
| name | text | 必須。銘柄名。JPX/J-Quants等の最新の権威ある銘柄マスターでコードとの一致を照合し、銘柄取り違え検出に使う |
| quantity | number | 必須。現在の保有数量。有限の正数 |
| average_cost_jpy | number | 任意。1株・1口当たり平均取得単価（円）。空欄または有限の正数とし、証券会社表示値を優先 |
| account_type | text | 任意。`NISA / 特定 / 一般` 等。口座番号は禁止 |

同じ銘柄を複数口座で保有する場合は口座ごとに行を分けてもよい。時価・集中度は `code` 単位で合算し、税務上の検討だけ `account_type` 単位で分ける。

保有数量の基準日はCSV列に持たせない。ユーザーの説明または直近アップロード時の文脈から確認し、不明かつ判断に影響する場合は質問する。

## 3. 入力と取得カバレッジ

計算前に各CSV行へ次の状態を付ける。複数の状態に該当する場合はすべて残す。

| 状態 | 条件 | 扱い |
|---|---|---|
| VALID | コード、名称、数量、現在値が有効 | 時価集計の対象 |
| ID_CONFLICT | コード・名称が空欄、コード形式不正、または最新の権威ある銘柄マスターでコードと銘柄名が不一致 | 解消まで計算対象外 |
| INVALID_QUANTITY | `quantity` が数値でない、0以下、または有限値でない | 解消まで計算対象外 |
| PRICE_MISSING | 有限の正の現在値を取得できない | 当該行の時価・全体構成比・HHIを厳密算出不能 |
| PREVIOUS_CLOSE_MISSING | 有限の正の前日終値を取得できない | 当該行と全体の前日比を厳密算出不能 |
| COST_MISSING | `average_cost_jpy` が空欄、有限値でない、または0以下 | 当該行、同一コード合計、全体の含み損益を厳密算出不能 |

- `ID_CONFLICT` と `INVALID_QUANTITY` は、値を推測・自動修正せずユーザーへ確認する。1行でも該当すれば、総時価、構成比、上位銘柄比率、HHI、全体損益を完全値として表示しない。
- `PRICE_MISSING` が1行でもあれば、総時価、構成比、上位銘柄比率、HHIを完全値として表示しない。取得済み行だけを示す場合は `取得済み銘柄の参考小計` とし、構成比を100%へ再正規化しない。
- `PREVIOUS_CLOSE_MISSING` は前日比だけを不完全にする。全行の現在値が揃っていれば総時価・構成比は算出できる。
- 同一コードの一部行だけが `COST_MISSING` の場合も、そのコード合計とポートフォリオ全体の含み損益を `一部取得単価不明・厳密算出不能` とする。判明行だけの損益は参考内訳に限定する。
- 欠損、競合、不正値を0として扱わず、黙って集計対象から除外しない。

## 4. 毎回再計算する値

CSVに計算結果を保存せず、レビュー時にWeb検索で現在値と前日終値を取得して再計算する。

- 時価円 = `quantity × 現在値`
- 前日比円/株 = `現在値 - 前日終値`
- 保有前日比円 = `quantity × (現在値 - 前日終値)`
- 取得原価円 = `quantity × average_cost_jpy`（取得単価がある場合のみ）
- 含み損益円 = `quantity × (現在値 - average_cost_jpy)`（取得単価がある場合のみ）
- 含み損益率 = `(現在値 ÷ average_cost_jpy - 1) × 100`（取得単価が正の場合のみ）
- 構成比 = `時価円 ÷ CSV内全行の時価円合計`（全行の現在値が取得できた場合のみ）
- 上位1・3・5銘柄比率は、同じ `code` を合算して計算する
- 銘柄HHI = `code単位の構成比²の合計`

現在値と前日終値には、取引所、価格種別、取得日時、URLを付ける。取引時間中の価格は遅延の有無を明記し、休場日・売買停止・株式分割・コード変更を確認する。取得単価が空欄なら含み損益を推測せず `算出不能` とする。

CSVに現金、投資信託、年金、不動産、負債がない限り、構成比とHHIは `CSV内の日本株保有内` の指標であり、総資産配分ではない。

## 5. データ取得の振り分け

- 通常の保有一覧更新: Web検索で現在値・前日終値を取得する。EDINET系MCPは発火しない。
- 決算・財務・セグメント・事業リスク・株主等が、保有継続や見直し判断に必要: 対象銘柄についてEDINET系MCPを発火する。
- 複数銘柄を確認する場合: 会社・証券コードの一括照合を優先し、重要度の高い銘柄から必要な項目だけ取得する。
- EDINETは現在株価や前日比の取得元として使わない。

## 6. ポートフォリオ診断

### 適合性

- 目標期間、流動性、許容損失と構成が整合するか
- 近い将来に必要な資金を変動資産へ置いていないか
- 個別株リスクを総資産ベースで過大評価・過小評価していないか

### 集中と相関

- 同一企業・系列、業種、国、通貨、顧客、サプライチェーンの重複
- 表面上は異なる銘柄でも、同じ景気・金利・規制・AI投資等へ依存していないか
- 固定上限を自動適用せず、許容損失と投資仮説の強さから評価する

### 投資仮説

- プロジェクトに保存された投資仮説を証券コードで対応づけ、`CHALLENGED / BROKEN / UNKNOWN` の銘柄と構成比を確認する
- 仮説ファイルに記録された次回レビュー期限の超過
- 現在価格で新規に買う場合にも成立するか
- 価格変化と事業事実の変化を分ける

### 税・コスト・代替案

- `account_type`、取得単価、実現損益、税、手数料。CSVだけで不明な項目は追加確認する
- 売却しない代替案: 新規資金で調整、配当再投資停止、レビュー待ち
- 個別株以外の現金・分散商品との機会費用

## 7. ストレステスト

ユーザー条件と保有実態に合わせ、少なくとも3シナリオを作る。

- 市場全体の下落
- 金利・為替の急変
- 最大テーマまたは主要保有の固有ショック

各ポジションの想定変化率、根拠、ポートフォリオ損失額、総資産への影響を分けて示す。粗い仮定による結果を精密予測として扱わない。

## 8. 出力

1. データ基準日と入力品質
2. 時価・損益・構成比一覧
3. 集中・相関・通貨・流動性
4. 投資仮説の健全性
5. ストレステスト
6. 税・コストを含む検討案
7. `今すぐ確認すべきこと / 今回は動かさないこと`
8. 次回レビュー日と、必要なら更新すべき `quantity / average_cost_jpy / account_type`

検討案は `追加調査 / 維持候補 / 新規資金で調整 / 段階的見直し / 売却検討` と表現し、自動的な売買命令にしない。
