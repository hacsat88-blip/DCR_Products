# 40 投資仮説の作成・追跡・ドリフト検出

## 目的

買った後に理由を作り替えないため、投資前または保有確認時に仮説、反証条件、確認指標を記録し、事実の変化だけを追跡する。

## 1. 仮説の作成

### 5文の中核

1. この事業は誰に何を提供し、どう現金を生むか。
2. 競争優位は何で、どの証拠があるか。
3. 経営・資本配分を支持する観察可能な実績は何か。
4. 現在価格に対して、どの仮定で安全余地があるか。
5. 間違っている場合の主要な損失経路は何か。

5文を書けない場合は、無理に完成させず `NoThesis / 判断保留` とする。

### 構造化記録

| 項目 | 内容 |
|---|---|
| thesis_id | 会社・日付を含む一意名 |
| created_at / updated_at | 作成・更新日 |
| data_cutoff | 使用データの基準日 |
| decision_label | ガバナンス定義の判断ラベル |
| core_thesis | 5文の中核 |
| key_assumptions | 検証可能な仮定 |
| evidence | 仮定を支える一次情報 |
| falsifiers | 仮説を反証する条件 |
| red_flags | 即時再調査を要する事象 |
| valuation_anchors | 価格ではなく入力仮定と範囲 |
| review_metrics | 指標、確認頻度、情報源 |
| next_review_date | 次回確認日 |

## 2. 仮定と反証条件

仮定は測定可能にする。

悪い例: `成長が続く`
良い例: `主力セグメントの数量成長が次の4四半期で前年同期比プラスを維持し、粗利率がX%を下回らない`

反証条件には次を含める。

- 事業ドライバー
- 競争優位
- 経営・資本配分
- 財務安全性
- 会計・統治
- 評価前提

株価下落だけを反証条件にしない。ただし価格上昇により期待収益が低下した場合は、事業仮説ではなく評価判断の変更として記録する。

## 3. 定期レビュー

各仮定を次で判定する。

- `CONFIRMED`: 新しい証拠が支持
- `UNCHANGED`: 重要な新情報なし
- `WEAKENED`: 反証ではないが確度低下
- `CHALLENGED`: 重要な反対証拠あり
- `BROKEN`: 事前定義した反証条件に該当
- `UNKNOWN`: 必要情報を確認できない

## 4. ドリフト分類

| 種類 | 定義 | 対応 |
|---|---|---|
| 事実ドリフト | 業績、競争、経営行動などが変化 | 仮説を更新し、判断を再評価 |
| 評価ドリフト | 価格・金利・為替・倍率が変化 | 期待収益と安全余地を再計算 |
| 表現ドリフト | 言い回しだけが変化 | 仮説変更と数えない |
| 基準ドリフト | 後から合格条件を緩めた | 元条件を保持し、変更理由を記録 |
| データドリフト | 定義、会計基準、連結範囲が変化 | 比較可能性を再構築 |

## 5. 意思決定ログ

更新時に次を追記する。

| 日付 | 新しい事実 | 影響する仮定 | 判定 | 判断変更 | 次の確認 |
|---|---|---|---|---|---|

過去記録を上書きせず、変更理由を残す。最終版は ChatGPT の「プロジェクトに保存」を使ってプロジェクトソース化し、ファイル名または見出しに証券コードを含めて `holdings*.csv` の `code` と対応づける。

仮説レビューで法定開示の財務履歴、事業リスク、経営・資本配分、主要株主等の確認が必要ならEDINET系MCPを発火する。単純な株価変動の確認だけでは発火せず、Web検索で価格基準日時と出所を確認する。

## 6. ニュース・株価異動への対応

ニュースを次に分類する。

- 会社固有の事実
- 規制・政策
- 業界・競合
- マクロ・金利・為替
- 市場ポジショニング・需給
- 根拠未確認の噂

時系列と一次発表を確認し、相関を因果と断定しない。短期価格変動だけなら仮説を変更せず、事前の反証条件に触れた場合だけ臨時レビューする。
