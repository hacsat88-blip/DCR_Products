## Conventional Commits

```
<type>: <description>
```

| type | 用途 |
|------|------|
| `feat` | 新機能 |
| `fix` | バグ修正 |
| `refactor` | リファクタリング（動作変更なし） |
| `docs` | ドキュメント変更 |
| `test` | テスト追加・修正 |
| `chore` | ビルド・CI・依存更新 |
| `perf` | パフォーマンス改善 |
| `ci` | CI/CD 設定変更 |

## コミットメッセージ規則

- 命令形で書く: "add" not "added"
- 72 文字以内（subject line）
- 本文が必要な場合は空行で区切る
- Breaking change は `!` を付加: `feat!: remove legacy API`

## ブランチ戦略

| ブランチ | 用途 |
|----------|------|
| `main` | 安定版。直接 push 禁止（P3） |
| `feat/<name>` | 機能開発 |
| `fix/<name>` | バグ修正 |
| `docs/<name>` | ドキュメント |
| `chore/<name>` | ビルド・CI・構造整理など非機能 |

## ネストした Git リポジトリ禁止

- リポジトリ内に別の `.git` ディレクトリを置かない（embedded git 禁止）
- サブプロジェクトを管理する場合は次のいずれかのみ許可:
  - **通常ディレクトリ**: 親リポジトリで直接追跡（推奨）
  - **submodule**: `.gitmodules` に明示登録し `git submodule add` で追加
- 既存の embedded git を発見した場合: `.git` を退避 → `git rm --cached <path>` → `git add <path>` で通常追跡に変換する

## PR ルール

- 1 PR = 1 目的（混ぜない）
- レビュー前にセルフチェック
- CI パス必須
- マージ後はブランチ削除
- **Squash Merge 原則** — clean linear history を保つ。`git revert` と `git bisect` が 1 コマンドで機能する状態を維持する
- **PR サイズ上限: 差分 150 行以内を目標** — 超える場合はフェーズ分割を検討する
- コミットは最低 1 時間に 1 回、タスク完了時に必ず行う

## マージ後の同期手順

PR マージ後は必ず次の順序でローカルを同期する:

```bash
git switch main
git pull --ff-only        # fast-forward のみ許可
git branch -d <作業ブランチ>  # マージ済みブランチを削除
git fetch --prune         # 削除済みリモートブランチのクリーンアップ
```

- `pull --ff-only` が失敗する場合は `git fetch` + `git log` で分岐原因を確認してから対処する
- マージコミットを main ローカルに作らない（squash merge 前提のため不要）

## Copilot / Agent 操作ルール

### ① ブランチ作成は事前承認必須（P3）

- 新しいブランチを作成する前に必ずユーザーへ目的・名前・影響範囲を提示し承認を得る
- 例外なし。緊急でも「このブランチを作成してよいか？」を一言確認する
- 承認を得た後に `git switch -c` を実行する

### ② 作業ブランチ完了後は去就を問い合わせ

- PR マージ完了またはタスク完了後、必ずユーザーに確認する:
  ```
  ブランチ <name> の作業が完了しました。
  このブランチを削除しますか？（削除 / 残す）
  ```
- ユーザーの回答を待ってから削除を実行する（削除は P3 扱い）
- 残す場合はブランチの用途をコメントとして提示する

### ③ ブランチが多い場合は整理を提案

- リモート/ローカルのブランチ数が **5本以上** になったら整理を提案する
- 提案時は次の分類を提示する:

  | 分類 | 条件 | 推奨 |
  |------|------|------|
  | 削除候補 | マージ済み / 30日以上更新なし | 削除を提案 |
  | 要確認 | 未マージで差分あり | ユーザーに確認 |
  | リスクあり | main との差分が大きい / 衝突の可能性 | 削除せず報告のみ |

- リスクありブランチは内容の概要を添えて報告し、ユーザー判断に委ねる
