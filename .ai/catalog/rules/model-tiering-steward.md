# Model Tiering Steward

サブエージェント委譲時のモデル階層選定を監督する。高級モデルを全工程で使う発想を捨て、
指揮（計画・統合判断）と実働（重推論・探索・定型作業）を分離し、各工程に必要十分な
モデルを割り当てることで、上限消費を抑えつつ上位モデルの賢さを必要な工程に集中させる。

## 前提（技術的事実）

- メインループのモデルは `/model` でユーザーだけが切り替えられる。Claude 自身は変更できない
- Claude Code のツール仕様として、Agent ツールおよび Workflow `agent()` には `model` パラメータがあり、
  サブエージェント単位で `fable` / `opus` / `sonnet` / `haiku` を指定できる（他環境では後述の degradation に従う）
- agent 定義の frontmatter `model:` で、特定エージェントのモデルを固定できる
- 「起点の可変」はメインループの切替ではなく、**指揮役ごと委譲する仮想指揮役パターン**で実現する

## When to activate

- サブエージェント / Workflow / 並列 orchestration の採用が決まったとき（pied-piper の発火モード決定後）
- ユーザーがコスト・上限・モデル使い分けに言及したとき
- 長時間の重実装・大規模探索など、モデル割り当てが消費に大きく影響するタスクのとき

## 複雑度分類

委譲設計の前に、タスクを次のシグナルで 重 / 中 / 軽 に分類する。

| 区分 | シグナル |
|---|---|
| 重 | 設計判断あり、影響ファイル多数、曖昧さ高、複数工程（計画→実装→レビュー）、正本変更、レビュー必須 |
| 中 | 仕様が概ね明確な単機能の実装・修正、影響範囲が限定的、工程が1-2段 |
| 軽 | 探索・列挙・定型変換・単純な調査、1工程で完結、判断要素が少ない |

## 階層別ルーティング表

| 複雑度 | 指揮役 | 委譲先 |
|---|---|---|
| 重 | メインループ（現行モデル）が指揮を保持 | 重推論・重実装 → `model: opus`、探索・列挙 → `model: sonnet` または `haiku` |
| 中 | **仮想指揮役**：分類と1回の委譲のみメインが行い、`model: opus` のサブエージェントに指揮役として丸ごと渡す | 仮想指揮役が必要に応じて Sonnet/Haiku へさらに割り振る（ネストは実用上1段） |
| 軽 | メインは委譲のみ、または一手で直接処理 | `model: sonnet` / `haiku` へ直接委譲 |

仮想指揮役パターンの狙いは、メインループの会話コンテキスト（最も高くつく部分）を
上位モデルで膨らませないこと。中タスクでメインが払うのは分類・委譲・結果受け取りの数ターン分に留める。

仮想指揮役がさらに下位モデルへ割り振る（ネスト委譲する）場合、その fan-out 計画
（委譲先の種類・モデル・並列数の見込み）を**最初の発火前提案に含め**、ユーザーの承認が
ネスト分も包含するようにする。承認範囲に含めなかった追加のネスト委譲を、サブエージェント側で
勝手に増やしてはならない。

## model-route スキルとの境界

`model-route` skill（cheap-default / 失敗してから昇格）は **単一セッション内のモデル選択・昇格戦略** を扱う。
本ルールは **サブエージェント委譲時の階層割り当て**（top-down の事前分類）を扱う。

- サブエージェント / orchestration を採用しない単独作業 → `model-route` に従う
- サブエージェント委譲が決まった場面 → 本ルールのルーティング表を優先する
- 両者が同時に候補化した場合、委譲の有無で一方だけを選ぶ（併用提示しない）

## 例外（複雑度に関わらず上位指揮）

次のいずれかに該当する場合、複雑度が中・軽でも指揮をメインループに残し、下位モデルへの丸投げをしない。

- セキュリティ・破壊的操作・P2/P3 操作が含まれる
- 正本（source-of-truth）変更、削除、依存変更が含まれる
- 金融・法務・外部送信が関わる
- pied-piper の承認ゲートを跨ぐ判断が必要

## 他環境への degradation

動的なサブエージェント単位のモデル指定は Claude Code 固有。他環境では次のように縮退する。

- **Codex**: 生成済み `.codex/agents/*.toml` の `model` / `model_reasoning_effort` で
  エージェント単位のモデルが**静的に**固定される。実行時の呼び出しごとの override はないため、
  本ルールは「ペルソナごとの静的な階層割り当て」として適用する。メインモデルの切替は
  `codex -m` / profile でユーザーが行う
- **Copilot / Cursor**: サブエージェントのモデル指定機構がないため、複雑度分類と
  「/model 相当の切替提案」（下記）のみ適用する

## /model 切替の推奨（補助）

セッション全体の作業の重さと現在のメインモデルが不釣り合いな場合
（例：軽作業が続くのに Fable 5 のまま → `/model sonnet`）、切替を一言だけ提案してよい。
切替の実行は常にユーザーに委ねる。同一セッションで同じ提案を繰り返さない。

## Invariants

- モデル指定（`model:` override）は必要十分な場合だけ行い、迷う場合は省略して継承に任せる
- 委譲しても pied-piper の発火モード（auto / propose / approve_required）と承認ゲートは省略しない
- 未検証の削減率・コスト数値を断定しない
- 下位モデルへの委譲で品質ゲート（レビュー・検証）を省かない。節約は速度と品質維持の手段であり目的ではない
