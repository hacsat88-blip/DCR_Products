# Autonomous QA Loop

## 基本原則

- ループには必ず明確な終了条件を設ける（無限ループ禁止）
- 修正スコープは最小限に制限し、副作用を防ぐ
- ループログは全イテレーションを記録し人間がレビューできるようにする

## ループ構造

```
[開始] テスト実行
   ↓
[判定] 全テスト通過?
   ├── YES → [完了] 成功報告
   └── NO  → 失敗テストを分類
               ↓
           修正可能か判断
           ├── NO（スコープ外・複雑） → [エスカレーション]
           └── YES → 修正試行
                      ↓
                  リトライカウンター +1
                  最大リトライ到達?
                  ├── YES → [エスカレーション]
                  └── NO  → テスト実行（先頭へ）
```

## 脱出条件（必須）

- **成功**: 全テスト通過
- **最大リトライ超過**: デフォルト3回（設定可）
- **タイムアウト**: デフォルト10分（設定可）
- **スコープ逸脱**: 指定外ファイルへの変更が必要な場合
- **同一失敗の繰り返し**: 同じテストが2回連続で失敗 → 異なるアプローチへ変更

## 修正スコープ制限

- 変更対象: テスト失敗に直接関連するファイルのみ
- 変更上限: 1イテレーション当たり最大3ファイル
- 禁止: 設定ファイル・テストコード自体の変更（テストを通すために書き換えない）
- 疑わしい場合はエスカレーション

## ループログ構造

```json
{
  "loop_id": "uuid",
  "iteration": 2,
  "timestamp": "2025-01-01T00:00:00Z",
  "test_results": {"passed": 10, "failed": 2},
  "failed_tests": ["test_auth_invalid_token"],
  "fix_applied": "src/auth.py:45 - token validation logic",
  "exit_reason": null
}
```

## エスカレーション時の報告内容

- 何を試みたか（試行履歴）
- 何が解決できなかったか
- 推定される根本原因
- 推奨する次のアクション
