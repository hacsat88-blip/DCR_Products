# Parallel Agent Patterns

## 基本原則

- 依存関係のないタスクは常に並列化する
- 競合書き込みを防ぐためにファイル単位で担当を分離する
- 部分失敗を許容し全体を停止させない設計にする
- コンテキストウィンドウ節約のため並列化は積極的に行う

## Fan-out / Fan-in パターン

```
Orchestrator
    ├── Agent A（独立タスク）
    ├── Agent B（独立タスク）
    └── Agent C（独立タスク）
         ↓ 全完了待機
    Result Merge
```

- Fan-out: タスクを独立したサブタスクに分解して並列起動
- Fan-in: 全エージェントの完了を待ち、結果を統合
- ショートサーキット: 全件不要な場合は最初の成功で終了

## 依存関係グラフ設計

1. タスクをノードとして列挙する
2. 依存関係をエッジとして定義する（A→B: AはBの前提）
3. トポロジカルソートで実行順を決定する
4. 依存なしノードを同一バッチとして並列起動する

## 担当ファイルの分離ルール

- 1エージェント = 1ファイル（書き込み競合ゼロ）
- 共有リソースへの書き込みは Orchestrator が一括担当
- 読み取り専用ファイルは複数エージェントが参照可

## 部分失敗ハンドリング

- **フェールファスト**: クリティカルパスのタスク失敗時のみ全停止
- **フェールソフト**: 非クリティカルなタスク失敗は記録してスキップ
- 失敗エージェントのリトライ: 最大3回、指数バックオフ
- 全タスク完了後に失敗サマリをレポート

## 結果マージ戦略

- ファイル変更: 互いに独立した変更なら単純結合
- JSON/設定ファイル: ディープマージ（後勝ちルールを明示）
- コード変更: 同一ファイルを複数エージェントが触らない

## コスト見積もり

- 並列度 N のコストは逐次の N 倍（時間は 1/N）
- トークン消費 = Σ（各エージェントのコンテキスト）
- コンテキスト最小化: 各エージェントには必要なファイルのみ渡す
