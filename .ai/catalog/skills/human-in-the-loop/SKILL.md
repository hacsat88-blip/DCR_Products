# Human-in-the-Loop

## 基本原則

- すべての自動化には脱出口（人間への引き渡し）を設計する
- 人間が関与すべき判断基準を事前に明示する
- 承認記録は監査証跡として永続保存する

## エスカレーション条件定義

以下のいずれかに該当する場合は人間承認を必須にする:

- **コスト**: 単一タスクの見積もりコスト > $X（チームで設定）
- **リスク**: 本番DB書き込み・外部API課金・権限変更
- **不確実性**: エージェントの自信スコア < 80%
- **新規パターン**: 過去に実行したことのないアクション
- **スコープ超過**: 変更ファイル数 > N、または指定外ディレクトリへのアクセス

## 承認フロー設計

```
Agent → 承認リクエスト生成
         ↓ (タイムアウト前)
Human → 承認 / 拒否 / 修正指示
         ↓
Agent → 承認内容に従い実行
         ↓
Agent → 実行結果を承認者に報告
```

- 承認リクエストには: 何を・なぜ・影響範囲・推定リスク を明記
- 拒否された場合の代替案を3つ用意する
- 修正指示は差分として受け取り再計画する

## タイムアウト・デッドライン処理

- 承認待ちタイムアウト: デフォルト30分（設定可）
- タイムアウト時の動作: フェールセーフ（何もしない）を原則とする
- 緊急時エスカレーション: 承認者不在の場合の代理人を事前定義

## 監査ログ要件

各承認イベントに以下を記録する:
- タイムスタンプ（ISO 8601）
- エージェントID・タスクID
- 承認内容（何を承認/拒否したか）
- 承認者ID
- 実行結果と成否

## 人間判断の学習活用

- 承認/拒否パターンを蓄積し自動化の閾値を継続改善する
- 月次レビュー: 不要な承認要求を特定し自動化対象へ昇格
- 却下理由を分析しエージェントの判断モデルを改善する
