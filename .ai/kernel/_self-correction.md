# Self-Correction Rules — ツール失敗時の対応規約

> deploy.ps1: `_` プレフィックスのため deploy 対象外（参照ドキュメント）

## 概要

ツールが失敗したとき、即座に同じことを繰り返すのは最悪の対応。
原因を特定し、アプローチを変え、それでも解決しなければ停止する。

**失敗から学ぶ: 同一パターンを繰り返さない。**

---

## 失敗時の対応フロー

```
1回目の失敗 → エラー解析 → 原因特定 → 修正して再試行
2回目の失敗 → アプローチ変更（別ツール・別方法）
3回目の失敗 → 停止してユーザーに報告
```

| 試行回数 | アクション | 禁止 |
|----------|-----------|------|
| 1 回目失敗 | エラーメッセージを完全に読む → 原因を特定 → 修正して再試行 | 変更なしで即再実行 |
| 2 回目失敗（同一操作） | アプローチを根本から変える（別ツール、別パス、別方法） | 同一コマンドを再度実行 |
| 3 回目失敗 | **停止** → 状況・試みた方法・推定原因をユーザーに報告 | 推測で強引に突破 |

---

## 再試行禁止パターン

以下は「再試行」ではなく「同一失敗の繰り返し」:

| ❌ 禁止 | ✅ 代替 |
|---------|---------|
| 同一コマンドを変更なしで再実行 | エラーメッセージを解析してから変更を加える |
| 権限エラーに sudo/--force で突破 | 権限の根本原因を調査してから対処 |
| ネットワークタイムアウトに即座にリトライ | 5 秒以上待ってから再試行（または原因を確認） |
| 「試してみましょう」で推測実行 | 「なぜ失敗したか」を先に特定する |
| エラーを無視して次の操作に進む | エラーが後続に影響しないことを確認してから進む |

---

## エスカレーション条件（即座に停止してユーザーへ報告）

以下の状況は自己修正を中止する:

| 条件 | 理由 |
|------|------|
| **環境依存の問題** | PATH、バージョン不一致、OS 差異は環境修正が必要 |
| **認証・権限の問題** | セキュリティ上、強制突破は禁止 |
| **外部サービスの障害** | 自分で解決できない |
| **5 回以上の連続失敗** | どのツールでも — ループに入っている証拠 |
| **データ消失・破損のリスク** | 安全を優先して停止 |

---

## エスカレーション報告フォーマット

```
🔴 停止: [操作の概要] で解決できませんでした

試みた方法:
  1. [1 回目の試み] → [エラー]
  2. [2 回目の試み] → [エラー]
  3. [3 回目の試み] → [エラー]

推定原因: [最も可能性の高い原因]

必要な対処:
  - [ユーザーまたは環境側で必要なアクション]

代替案: [別のアプローチがあれば提示]
```

---

## 失敗からの学習

セッション内で解決した問題:
- 次回同じパターンが出たら同じ修正を適用する
- mem_cli.py quick-save で重要な解決策を記録する候補とする

セッション内で未解決だった問題:
- エスカレーション報告をそのままメモリに保存する
- 次回セッション開始時に報告された内容を確認する
