# Repo Map

Purpose:
Help the assistant understand the project structure and conventions
before proposing changes.

Behavior rules:

- infer the repository structure before suggesting edits
- prefer existing patterns instead of introducing new ones
- preserve architecture and naming conventions
- recommend minimal changes in the correct layer
- avoid cross-layer coupling unless redesign is requested

When uncertain:

- point to the most likely file or layer that should be inspected
- state assumptions explicitly

## Main Directories

Repository governance model:

- Source layer: editable canonical assets (`.ai/kernel/`, `.ai/catalog/rules/`, `.ai/catalog/skills/`, `templates/`, `.ai/catalog/agents-source/`)
- Runtime layer: tool entrypoints read directly by each editor (`.github/`, `AGENTS.md`, `CLAUDE.md`)
- Generated layer: deploy outputs and mirrors (`.claude/agents/`, `.codex/agents/`; large mirrors are Git-ignored)
- Workspace layer: docs and operations scripts (`docs/`, `deploy.ps1`, `validate.ps1`, `init-project.ps1`)

Unsafe migration rule:

- Do not move `.ai/catalog/rules/` or `.ai/catalog/skills/` into runtime/generated mirrors
- Do not delete `templates/` while `init-project.ps1` reads from it
- Do not overwrite runtime entrypoints from templates without an explicit migration plan
- Do not manually edit `AGENTS.md`, `CLAUDE.md`, or `.github/copilot-instructions.md` — these are regenerated by `deploy.ps1`
- Any future path migration must support old and new paths in parallel before deletion

## Execution Layer

.github/copilot-instructions.md
VS Code Copilot entry point. DCR Kernel with Permission model (P1/P2/P3)
and routing priority.

AGENTS.md
Codex / GitHub Copilot CLI entry point. DCR Kernel + module behaviors.
Copilot CLI specific behavior is documented in `.ai/environments/copilot-cli/kernel.md`.

CLAUDE.md
Claude Code entry point. DCR Kernel + safety boundaries + permission model.

.ai/
AI system kernel, repo map, routing design, and behavior modules.

.ai/kernel/
共通カーネル正本。全エディタの入口ファイルはこの思想を継承。

.ai/repo-map.md
このファイル。プロジェクト構造と規則の参照用。

.ai/rule-routing-design.md
ルール動的参照の設計文書。単一ソース原則、auto-load 安全条件、
エディタ別マッピングを定義。

.ai/module/
Specialized behavior modules (architecture, debugging, review, prompting).

.ai/kernel/gates/
Trigger-activated gate definitions (a/, i/, r/, s/, d/, p/, q/, sh/).
旧 `.commands/` は `.ai/kernel/gates/` に統合済み。

.ai/kernel/dcr-kernel.md
Shared runtime kernel source. Runtime entrypoints are generated from this file.

## Deploy

deploy.ps1
一方向同期スクリプト。repo-local entrypoint と generated mirror を source-of-truth から再生成する。

- .ai/catalog/agents-source/*.toml → .codex/agents/ (Codex, Git 管理外)
- .ai/catalog/agents-source/*.md → .claude/agents/ (Claude Code, Git 管理外)

オプション: -Target (all/vscode/cursor/agents/dcr), -DryRun, -Check (drift検出)。

sync-agents.ps1
レガシー: deploy.ps1 -Target agents に統合済み。互換性維持のため残存。

## Project Init

init-project.ps1
新規プロジェクト向け AI 指示ファイル生成スクリプト。
templates/ のテンプレートと project-context.md を入力に、
CLAUDE.md / AGENTS.md / .github/copilot-instructions.md の3ファイルを生成。
共有リソース (.ai/kernel/, .ai/module/) もコピーする。
オプション: -ProjectPath (必須), -ContextFile, -Target (all/claude/codex/copilot), -SkipShared, -DryRun。

## Architecture Notes

Preferred layering:
copilot-instructions.md → kernel.md → module/*.md + .ai/kernel/gates/*.md

Configuration pattern:
Markdown-based instruction files, no code dependencies.

Deployment pattern:
deploy.ps1 regenerates runtime entrypoints and repo-local generated mirrors from `.ai/` source-of-truth.
One-way only: repository → editor. Never reverse.

## Change Rules

When modifying this repository:

- edit `.ai/catalog/rules/`, `.ai/catalog/skills/`, `templates/`, and `.ai/catalog/agents-source/` here, then deploy if needed
- prefer minimal diffs
- preserve existing naming conventions
- do not create files in templates/ unless archiving a new editor config or managing project init templates
- do not modify generated mirrors directly
- do not treat `.claude/agents/` or `.codex/agents/` as editable source paths
- do not perform one-shot move + overwrite + delete migrations for folder restructuring
