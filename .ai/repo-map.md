# Repo Map

Purpose:
Help an assistant understand the current repository structure and choose the correct source layer before proposing or making changes.

Behavior rules:

- Inspect the repository structure before editing.
- Prefer existing patterns over new abstractions.
- Edit source-of-truth files first, then regenerate mirrors.
- Keep changes minimal and in the correct layer.
- Do not revive retired runtime surfaces or product-specific assets.

When uncertain:

- Inspect the most likely source file first.
- State assumptions explicitly.
- Treat generated outputs as evidence, not as the canonical edit target.

---

## Project Summary

This repository is the Mac triad source-of-truth for shared AI working instructions.

Canonical runtime surfaces:

- Codex
- Claude Code
- Cursor

Main purpose:
Manage shared rules, skills, agents, and kernel instructions for the triad. Product implementation files, local machine state, retired editor mirrors, sample data, and generated caches are outside the canonical source-of-truth.

Tech stack:
Markdown configuration, PowerShell deployment, GitHub version control.

Package manager:
N/A. This is a configuration and instruction repository.

## Main Directories

Source layer:

- `.ai/book/` - shared operating book.
- `.ai/kernel/` - shared runtime kernel, gates, triggers, and permission model.
- `.ai/catalog/rules/` - canonical shared rules.
- `.ai/catalog/skills/` - canonical shared skills.
- `.ai/catalog/agents-source/` - canonical agent source definitions.
- `.ai/environments/` - triad-specific environment deltas.

Generated/runtime layer:

- `AGENTS.md` - Codex entrypoint.
- `CLAUDE.md` - Claude Code entrypoint.
- `.cursor/` - Cursor mirror.
- `.codex/agents/` - generated Codex agents.
- `.claude/agents/` - generated Claude agents.

Tooling layer:

- `deploy.ps1` - generate and check triad runtime outputs.
- `validate.ps1` - structural validation and deploy dry-runs.
- `tools/` - adapters, manifest tooling, and validators.

Retired or excluded layers:

- product implementation files and sample product data.
- retired editor mirrors and vendor-specific legacy surfaces.
- local secrets, local config, caches, and machine-specific runtime state.

## Deploy

Use `deploy.ps1` to generate runtime outputs from `.ai/`.

Common commands:

```powershell
pwsh -ExecutionPolicy Bypass -File .\deploy.ps1 -Check
pwsh -ExecutionPolicy Bypass -File .\deploy.ps1 -Target codex
pwsh -ExecutionPolicy Bypass -File .\deploy.ps1 -Target claude
pwsh -ExecutionPolicy Bypass -File .\deploy.ps1 -Target cursor
pwsh -ExecutionPolicy Bypass -File .\deploy.ps1 -Target agents
```

Allowed triad targets are `codex`, `claude`, `cursor`, and `agents`.

---

## Validation

Use `validate.ps1` for repo integrity:

```powershell
pwsh -ExecutionPolicy Bypass -File .\validate.ps1
```

Validation should confirm:

- rule and skill structure.
- routing index freshness.
- skill capability metadata.
- deploy dry-runs for triad targets.
- generated mirror and entrypoint consistency.

---

## Change Rules

When modifying this repository:

- Edit `.ai/book/`, `.ai/kernel/`, `.ai/catalog/`, or `.ai/environments/` first.
- Regenerate generated outputs with `deploy.ps1`.
- Keep local settings, secrets, product implementation files, sample data, and caches out of Git source-of-truth.
- Do not add new runtime surfaces unless the triad scope is explicitly changed.
- Do not treat `.cursor/`, `.codex/agents/`, or `.claude/agents/` as canonical source files.
