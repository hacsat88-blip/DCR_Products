# Quality Floor Rules — 完了宣言の最低要件

> deploy.ps1: `_` プレフィックスのため deploy 対象外（参照ドキュメント）
> inherits: coding-standards, testing-standards

## 概要

「完了」「修正済み」「動作確認済み」は証跡なしに使ってはならない言葉。
主張はすべて、今実行した検証結果で裏付けること。

**安全上の留保・重要な未確定情報は必ず明示する。**

---

## 完了宣言の必須証跡

いかなる完了宣言にも、以下の **4 つの証跡がすべて必要**:

| 証跡 | 確認方法 | 注意 |
|------|----------|------|
| **ビルド/コンパイル通過** | `npx tsc --noEmit` / `cargo build` 等が exit 0 | 型エラーがないこと |
| **関連テスト pass** | `npm test` / `pytest` 等で対象範囲のテストが green | 新規コードは新規テスト必須 |
| **Lint 通過** | ESLint / flake8 等が warning 以下 | error は絶対に残さない |
| **Fresh verification** | 上記を「今実行した」結果であること | 過去のキャッシュ・目視のみ不可 |

---

## 完了として認めない表現

以下の表現で締めくくる応答は完了ではない:

| ❌ 不完全な表現 | ✅ 代替 |
|----------------|---------|
| "should work" | 実際に実行して結果を示す |
| "probably fixed" | テストを実行して green を確認する |
| "seems correct" | コンパイルを通してから報告する |
| "テストを書く必要がある" | テストを書いてから完了とする |
| "目視で確認しました" | スクリーンショットか具体的な出力を添付 |
| "おそらく問題ないはずです" | 問題がないことを検証してから報告 |

---

## 部分完了の報告フォーマット

完全な検証が不可能な場合（環境制約、外部依存など）:

```
✅ 検証済み:
  - [具体的に検証した内容]
  - [コマンドと出力]

⚠️ 未検証:
  - [検証できなかった内容]
  - リスク評価: [低/中/高] — [理由]

次のステップ:
  - [検証に必要なコマンドや手順]
```

---

## 検証の信頼性レベル

| レベル | 定義 | 受け入れ可否 |
|--------|------|-------------|
| 🟢 Gold | CI が green、全テスト pass、本番同等環境で検証 | 常に可 |
| 🟡 Silver | ローカルで全テスト pass、lint clean | 可（CI 通過を別途確認） |
| 🟠 Bronze | 該当ファイルのテストのみ pass | 条件付き可（範囲を明示） |
| 🔴 None | 検証なし・目視のみ | 不可 |

完了宣言は Silver 以上を原則とする。Bronze の場合は範囲を明示する。

---

## 検証コマンドの例

プロジェクト種別に応じた検証コマンド（プロジェクトに合わせて調整）:

```bash
# TypeScript / Node.js
npx tsc --noEmit && npx vitest run && npx eslint src/

# Python
python -m pytest && python -m mypy . && python -m flake8

# PowerShell
pwsh -File validate.ps1 && pwsh -File deploy.ps1 -Check
```
