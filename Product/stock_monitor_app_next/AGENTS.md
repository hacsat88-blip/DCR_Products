# AGENTS.md

## Project
stock-monitor

## Goal
日本株の銘柄選定と監視を行うフロントエンドアプリを構築する。
単なる株価表示ではなく、利益の質・成長性・壊れにくさを見ながら候補を絞れることを重視する。

## Current Phase
現在は Phase 1。
フロントエンド完結の実装を優先する。
実データ接続、通知、バックテストはまだ実装しない。

## Must Preserve
- 既存 v3 の画面構成
- 既存 v3 の情報設計
- 既存 v3 の文言の役割
- 段階的リファクタを行うこと
- 全面リメイクしないこと

## Product Principles
- 安い株ではなく、芯のある株を探せること
- 数字だけでなく、短い説明文と散文サマリーも持つこと
- 「探す → 比べる → 監視する → 崩れを見抜く」が一画面体験としてつながること
- UIは金融ダッシュボード風だが、可読性を最優先すること

## Design Direction
- ダークテーマ
- 濃紺グラデーション背景
- KPIカード
- 見やすいチャート
- 情報の階層を明確にする
- 文字を小さくしすぎない
- 情報過多にせず、余白を残す
- 本文最小 14px
- 主要数値 24px 以上
- 色だけで状態を区別しない
- デスクトップは右ドロワー
- モバイルはフルスクリーンモーダル

## Tech Direction
- Next.js + TypeScript
- Tailwind CSS
- Recharts
- Zustand または React Context
- localStorage を使った軽い永続化
- services 層を分離して、後でAPI差し替えしやすくする

## Phase Boundary
今回は以下を実装しない:
- 認証
- バックエンド
- DB
- 実API接続
- 通知基盤
- サーバーアクション
- 過剰なUIライブラリ導入

## Data Model
初期銘柄:
- 日本通信（9424）
- いちご（2337）
- BASE（4477）
- Finatext HD（4419）

## Scoring Policy
本命度は以下を軸にした仮スコアとする:
- 売上成長率
- 営業利益成長率
- 営業CF
- バリュエーションの過熱度
- 希薄化や一過性利益への警戒

action の暫定ルール:
- buy_now:
  - revenueGrowth > 15
  - opGrowth > 15
  - operatingCF > 0
  - PER <= 30
- wait_earnings:
  - 成長はあるが、M&A寄与や一過性要因の確認が必要
- wait_pullback:
  - 成長は強いが、PER > 40 など過熱感あり
- exclude:
  - operatingCF が大きくマイナス
  - 希薄化懸念あり
  - 一過性利益依存

## Do

- コンポーネントを適切に分割する
- 型定義を明確にする
- mock データを差し替えやすくする
- README を整える
- IMPLEMENTATION_NOTES.md または CHANGELOG.md を用意する
- 将来API接続箇所がわかるようにする

## Don’t
- いきなりバックエンド前提にしない
- 単一ファイルにロジックを詰め込まない
- 見た目優先で可読性を落とさない
- モックデータに強く依存した密結合設計にしない
- 不要なライブラリを増やしすぎない
- 全面リメイクしない
